What it is

A production-workflow agent, not a copy generator

The Experience Production Agent is AEM’s agent for turning natural-language requirements into content-production work — updating existing experiences, creating new pages, generating forms, converting designs into structured content, and producing personalized communications.

It sits inside AEM’s broader Brand Experience Agent structure. The value is in the workflow, not just the words: it interprets a requirement, plans, produces a reviewable change, and hands off for human review and governance before anything ships.

Current documentation lists five primary jobs — Content Update, Content Create, Figma to Visual Content Fragments, Form Creation, and Communication Creation — each detailed below.

Getting the words right

Agent, job, skill, orchestrator

These terms are related but not interchangeable:

TermMeaning
Experience Production AgentThe specialist responsible for production workflows.
JobA user-facing task, such as Content Update or Form Creation.
SkillThe underlying capability invoked by the agent or an orchestration layer.
AI AssistantA conversational interface used to invoke supported jobs.
Agent OrchestratorThe layer that interprets intent and coordinates one or more agents.

A single business request can span several capabilities. For example:

“Find the approved campaign image, create a banner version, update the homepage, and prepare it for review.”

could involve Discovery, Content Optimization, Experience Production, and Governance. The user describes the business outcome; the orchestration layer determines the individual steps.

The clearest entry point

Content Update

The Content Update job modifies existing AEM Sites pages, Content Fragments, forms, assets, and individual page elements — headings, buttons, images, sections — adding, removing, replacing, or modifying content from natural-language instructions.

Supported inputs: natural-language requirements, AEM author URLs, public publish URLs, Jira tickets, PDFs, screenshots, and visual annotations.

Basic workflow

  1. Provide the target page URL.
  2. Describe the requested changes.
  3. Review the agent’s interpretation or result.
  4. Open the preview, launch, or version.
  5. Refine the content in authoring.
  6. Apply or publish after approval.

Example

Update this page:

https://www.example.com/us/summer-sale

Make these changes:

- Change the hero headline to "Summer starts here".
- Replace the hero image with the approved asset at
  /content/dam/campaigns/summer/hero.jpg.
- Change every "Shop Now" button to "Explore the collection".
- Remove the expired countdown banner.
- Preserve the existing layout.

Prepare a reviewable result. Do not publish.

Author URL versus publish URL

You can target either an author URL or a public-facing publish URL. Using a public URL requires a one-time configuration so AEM can map the public page back to its content source — and that configuration requires System Administrator or Product Administrator rights.

Non-destructive behavior

The central safety model

For AEM as a Cloud Service, the job creates a new launch; for Document Authoring, a new version. The agent prepares a reviewable change rather than silently overwriting the current experience. Jira-triggered updates also return progress comments and links to the resulting preview or changes.

Jira workflow

A Jira ticket can carry the target page, a natural-language requirement, an annotated screenshot, a PDF, or a document describing the change. The agent posts status updates back to the ticket with a link to the resulting preview or content changes.

Input limitation worth knowing

File uploads are supported when interacting through Jira, but not when interacting through the AI Assistant.

Universal Editor refinement

After the initial update, authors can open the result in the Universal Editor, select a component or text element, and ask the AI Assistant for a focused refinement — the Assistant uses the selected element as context, so there’s no need to describe the target manually.

Make this headline more engaging for 30–40-year-old coffee drinkers.

Rewrite this paragraph for a technical B2B audience.

Shorten this CTA to fewer than 25 characters without changing its meaning.

Bulk operations

The agentic-capability catalog describes bulk use cases: replacing text across many pages, updating pages under an AEM path, editing hundreds of Content Fragments, creating fragments, updating fields, tagging, publishing, and applying the appropriate governance workflow.

Find all Content Fragments under /content/dam/products
where the calories field is 150.

Change calories to 200, update the Serving Style field to "Iced",
and return the affected fragments before publishing.

Bulk is higher-risk than a single update

Bulk actions have a larger blast radius. Start with a limited path, require a preview or dry run where available, and review the affected-object list before activation.

New pages from a brief

Content Create Limited Availability

The Content Create job builds new, on-brand AEM pages from a natural-language prompt, a marketing brief, and an AEM template.

The brief can describe business goals, target audience, topics, keywords, desired word count, required sections, and messaging constraints. The agent first produces a plan for review, then generates the page against the selected template, adjusting the number of sections to fit the brief.

Example

Create a product landing page under:

/content/site/us/en/products/coffee-maker-5000

Use the approved Product Detail Page template.

Use the attached brief to create:

- Hero section
- Product summary
- Three product benefits
- Technical specifications
- Customer testimonial
- FAQ
- Primary CTA

Target audience: first-time premium coffee-machine buyers.
Target length: approximately 900 words.
Prepare the page for review. Do not publish.

The plan-review step earns its place: it lets the author catch an incorrect page type, missing sections, the wrong audience, excessive word count, unsupported claims, or an incorrect CTA strategy before generation.

Content Create is documented as Limited Availability and requires manual onboarding.

Design into structured content

Figma to Visual Content Fragments

This job converts an approved Figma design into AEM structures for Visual Content Fragments — Content Fragment Models, Content Fragments, HTML visualization templates, and any associated assets or layout structures. Where suitable models or fragments already exist, it reuses them rather than rebuilding from scratch.

Prerequisites

The Figma workflow requires authentication. The Figma user must generate a Figma personal access token, sign in to Adobe Experience Cloud, persist the token through the AEM Figma-to-Content-Fragment configuration, and provide a Figma share link to the design object. The configuration URL:

https://experience.adobe.com/#/aem/figmatocontentfragment

Example

Import this Figma design into AEM:

https://www.figma.com/design/example

Use the AEM program and environment associated with:
https://author.example.com

Reuse an existing product Content Fragment Model if one matches.
Create the required Visual Content Fragment and HTML template.
Return links to the model, fragment, and template.

What it is not

Not an image importer. The point is to move from design to reusable structured content:

Figma design
→
Content structure
→
Content Fragment Model
→
Content Fragment
→
HTML visualization template
→
Previewable modular experience

A Content Fragment holds structured editorial data; the HTML template supplies the visual presentation. That separation is what makes the result reusable across supported channels.

Adaptive Forms from language or PDFs

Form Creation

The Form Creation job builds Adaptive Forms from natural-language requirements — generating a form from a plain-text description, inferring field types, applying an approved template, or importing and converting a PDF (detecting fields, preserving layout, adding responsive behavior and validation, and saving to a specified AEM path).

Creation modes

Plain-language creation

Create an employee onboarding form with:

- Full name
- Employee ID
- Department
- Start date
- Manager
- Equipment requirements
- Accessibility accommodations
- Privacy consent

Make name, employee ID, department, and start date required.
Use the approved HR form template.
Save it under the onboarding forms folder.

PDF conversion

Convert the attached insurance enrollment PDF into an Adaptive Form.

Preserve the document structure where possible.
Identify required fields.
Add email and date validation.
Make the result responsive.
Use the approved Core Components form template.
Save it under /content/forms/insurance/enrollment.

Template choices

The user chooses between a Core Components-based template and an Edge Delivery Services-based template, and specifies the save path. For an Edge Delivery Services form, the workflow can additionally use a specified GitHub repository.

What requires human review

The agent generates the structure — it does not make the form automatically compliant with every business, legal, accessibility, or security requirement. Still test: required vs. optional fields, labels and semantics, accessibility, keyboard navigation, screen-reader behavior, conditional rules, validation edge cases, the submission endpoint, privacy and consent language, mobile layout, error messages, data retention, and integration behavior.

Output, not intake

Communication Creation Alpha

The Communication Creation job creates Interactive Communications — personalized, data-driven documents for business correspondence such as account statements, policy documents, bills, welcome kits, benefit notices, loan statements, and settlement letters.

This is the mirror image of a form:

FormInteractive Communication
Collects information from a userGenerates information for a recipient
Usually interactive and submittedUsually rendered as correspondence
Input-orientedOutput-oriented
May be web-basedCommonly generated for print or PDF

The job creates personalized correspondence for print, with PDF as the documented output format. It can work from approved organizational templates, PDFs, JPG or PNG images, and even hand-drawn templates — analyzing the source to identify fields, preserve layout, and create data-driven correspondence.

Example

Create a vehicle-insurance claim settlement communication.

Use the approved correspondence template.

Include:

- Customer name
- Policy number
- Claim number
- Settlement amount
- Settlement date
- Required disclaimer
- Signature area

Generate a reviewable PDF-oriented Interactive Communication.

Communication Creation is documented as alpha; participation requires early-access onboarding through Adobe.

Working with other agents

How the jobs work together

A realistic end-to-end update rarely lives in one job. The agent can obtain source assets from a discovery capability, produce the change, and pass the result to governance — for example:

  1. Marketer → AssistantRequest a campaign page update
  2. Assistant → DiscoveryFind approved campaign assets
  3. Discovery → AssistantReturn candidate assets
  4. Assistant → ProductionUpdate the page using the selected asset
  5. Production → AEMCreate a launch or preview
  6. AEM → ProductionReturn a reviewable result
  7. Production → AssistantReturn the preview link
  8. Assistant → GovernanceCheck brand and policy alignment
  9. Governance → AssistantReturn findings
  10. Assistant → ReviewerShow preview and governance results
  11. Reviewer → AEMApprove, refine, or publish

Availability is not uniform

Do not assume every multi-agent sequence is available in every interface. The exact orchestration depends on the enabled skills, deployment, entitlement, and user surface.

Where it runs, what it needs

Access and prerequisites

Deployment

AEM agents are available for AEM as a Cloud Service and Edge Delivery Services, with progressive availability for AEM 6.5 LTS Managed Services through co-innovation, and AEM on-premises excluded. Because documentation paths differ, verify eligibility for the specific organization, product, and job.

Access paths

  • AEM AI Assistant
  • Jira for Content Update workflows
  • Universal Editor for contextual refinement
  • AEM Playground or trial programs
  • Agentic SKU access
  • Early-access onboarding for specific jobs

Activation information

Content Update activation may request the IMS Organization ID, product_id, and profile_id. For Edge Delivery Document Authoring, it may additionally request the relevant domains, GitHub organization, repository, and branch.

Why it’s safe to adopt

The safety model

Non-destructive changes. Strongest for Content Update: AEM as a Cloud Service creates a new launch, Document Authoring a new version, and Jira returns preview links and progress comments. The author still decides whether to apply or publish.

Plan before generation. Content Create produces a plan before generating the page — review it for the correct template, structure, audience, and content scope, and for any unsupported or risky claims.

User-guided refinement. The Universal Editor lets an author select a specific element and refine it conversationally instead of rerunning the entire page-generation process.

Human review remains mandatory

AI-generated responses may be inaccurate or misleading. Always verify text, claims, page structure, images, form fields, validation rules, data mappings, correspondence layouts, accessibility, rights, and the final publication state.

Getting reliable output

A prompting formula

A reliable prompt names the action, the target, the source material, the template or policy, the constraints, the output required, and the approval boundary.

Weak prompt

Rolling it out

A recommended operating model

Start with low-risk work

Single-page text updates, CTA changes, small Content Fragment edits, draft form generation, Visual Content Fragment prototypes, and non-production previews.

Then introduce scale

Once the team trusts the workflow: bulk page replacement, bulk Content Fragment updates, Jira-driven production requests, PDF-to-form conversion, Figma-to-AEM workflows, and reusable page-generation templates.

Use explicit approval gates

GateReview
InputIs the brief, screenshot, PDF, or design authoritative?
ScopeAre the target paths and environments correct?
PlanIs the proposed content structure correct?
OutputAre the generated changes technically and editorially correct?
GovernanceAre brand, rights, accessibility, and policy checks satisfied?
ActivationIs the change approved for publication?

Measure the value

Useful metrics: time to complete a page update, time from brief to first draft, manual authoring steps and handoffs eliminated, form-creation and Content-Fragment-update time, percentage of changes requiring rework, review time per change, bulk-update accuracy, false-positive/false-negative rates, and production changes made without rollback.

Setting expectations

Common misconceptions

MisconceptionReality
“It’s just a chatbot.”It interprets requirements, invokes AEM operations, creates structured outputs, and returns reviewable changes.
“It publishes directly to production.”Content Update is built around launches, versions, or previews; publishing stays a separate decision.
“Content Create replaces content strategy.”The quality of the brief, template, source material, and governance rules strongly shapes the output.
“Figma import produces a finished website.”It translates a design into structured models, fragments, and HTML visualization templates.
“Form Creation makes the form production-ready.”It accelerates structure and configuration; accessibility, integrations, privacy, validation, and UAT still need review.
“All jobs have the same availability.”Content Create is Limited Availability; Communication Creation is alpha; others depend on organization, environment, and onboarding.
“Bulk editing equals single-page editing.”Bulk actions have a larger blast radius and need stricter scoping, preview, and approval controls.

Learn it safely

A practical learning lab

Lab 1 · Single-page update

Update one non-production page.
Change one headline and one CTA.
Prepare a launch or preview.
Review the result without publishing.

Learn: target selection, prompt specificity, launch/version behavior, review workflow.

Lab 2 · Visual requirement

Attach a screenshot showing the desired change.
Ask the agent to reproduce it on a preview page.

Learn: visual-input interpretation, layout preservation, the gap between requested and actual result.

Lab 3 · Content Fragment update

Find Content Fragments with a specific field value.
Change one field.
Return the affected paths before activation.

Learn: structured-content targeting, bulk scope, field-level changes.

Lab 4 · Form creation

Generate a small feedback form.
Review fields, validation, accessibility, and submission behavior.

Learn: template selection, field inference, validation review.

Lab 5 · Figma conversion

Import a simple approved Figma card design.
Inspect the generated model, fragment, and HTML template.

Learn: design-to-content mapping, model reuse, Visual Content Fragment output.

Lab 6 · End-to-end orchestration

Find an approved asset,
create a rendition,
update a preview page,
run brand checks,
and stop before publishing.

Learn: agent handoffs, review-package construction, governance boundaries.

If you remember ten things

The ten that anchor everything

  1. The Experience Production Agent is for executing content-production work.
  2. Its jobs are Content Update, Content Create, Figma to Visual Content Fragments, Form Creation, and Communication Creation.
  3. Content Update changes existing pages, Content Fragments, forms, and assets.
  4. Content Update uses launches, versions, or previews to support review.
  5. Content Create turns a prompt, brief, and template into new pages.
  6. Figma import creates structured AEM content — not merely screenshots or images.
  7. Form Creation generates forms from text or reconstructs them from PDFs.
  8. Communication Creation produces personalized Interactive Communications and is currently alpha.
  9. Bulk operations need stricter scope and review than single-object updates.
  10. The agent accelerates production, but human editorial, legal, accessibility, governance, and publishing decisions remain necessary.
