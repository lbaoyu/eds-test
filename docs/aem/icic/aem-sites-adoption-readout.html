Prioritized feature opportunities

Four focused opportunities.

Start with authoring friction and broader XF reuse, then qualify new native capabilities. Confirm business value and technical fit before implementation; feature nonuse does not mean the existing approach is wrong.

01
Deepen existing use

Authoring flexibility

Today
Rigid template/component mappings were reported. Editable Templates, Content Policies, and the Style System are already in use.
Next
Test blocked authoring tasks. Establish whether the constraint is intended governance, a policy, component code, or guidance; apply the appropriate remedy.
Illustrative use case

Allow a suitable existing component on an approved template if its policy is the blocker.

Proceed whenThe root cause is confirmed and the change is approved. Template Editor access requires ICICI IT approval; no blanket Style System expansion is proposed.

02
Extend reuse · assess integration separately

Experience Fragments beyond header and footer

Today
Experience Fragments are used only for the header and footer. XF integration with Target is not used.
Next
Extend reuse to other repeated, approved page sections where shared content and layout fit. Assess Target export separately for a defined personalization use case.
Candidate use cases · validate fit

A reusable campaign banner, product-promotion block, or service notice across relevant pages. These are sample opportunities, not confirmed implementation gaps.

Proceed whenRepeat usage, approval ownership, variation needs, and shared-update impact are confirmed. For Target export, also confirm entitlement and integration fit.

03
Qualify new adoption

Launches for future content

Today
Launches is not used. A need for parallel future-content versions remains unconfirmed.
Next
Establish whether authors need to prepare future updates while maintaining current pages. If relevant, demonstrate Launches in nonproduction.
Illustrative use case

Prepare a product-campaign refresh alongside current content. This is a sample scenario, not a confirmed ICICI campaign.

Proceed whenPlanning need, promotion behavior, and approval compatibility are validated. Launches does not replace maker-checker approval or resolve the custom bulk-publishing issue.

04
Qualify native delivery

GraphQL for Content Fragments

Today
CF models and a custom encrypted-JSON servlet are used. Native GraphQL delivery is not used.
Next
Assess native GraphQL against a defined consumer use case. Preserve encryption, authentication, and consumer contracts.
Illustrative use case

Request selected structured-content fields. Compare functional fit and operating effort; benefits have not been measured.

Proceed whenVersion, architecture, and consumer/security requirements are confirmed before any migration. Existing CF and custom delivery retain credit; native GraphQL remains unadopted.

Adoption roadmap

Validate fit, demonstrate value, then extend.

Sequence gates rather than calendar commitments. No additional feature rollout, license entitlement, delivery effort, or business benefit is assumed to be approved.

01 · confirm

Validate the use case

Review the 12 feature-adoption statuses and authoring blockers. Identify repeated page sections suitable for XF reuse beyond the header and footer. Qualify use cases for Launches, XF/Target, and GraphQL.

Exit: an agreed baseline and a short list of relevant use cases.

02 · demonstrate

Test a relevant example

Test the justified authoring remedy or one suitable reusable XF experience in nonproduction. Validate ownership, approvals, and shared-update behavior. Demonstrate Launches, XF/Target, or GraphQL only after business fit and prerequisites are confirmed.

Exit: a reviewed task demonstration, preserved controls, and an explicit proceed / do-not-proceed decision.

03 · embed

Measure sustained use

For approved changes, agree ownership, author guidance, and a modest follow-up sample. Extend only to comparable use cases; do not standardize every template or component without a need.

Exit: repeatable confirmation of relevant usage and outcomes, not simply a higher feature count.

Measures for a more mature follow-up

Author independenceObserved completion of agreed authoring tasks without unplanned developer intervention; record intended controls separately. No baseline is available yet.
Relevant feature reachEligible tasks, components, or release scenarios using the selected feature / the agreed eligible population. Establish eligibility before calculating a percentage.
Adoption depthRepeat use, named ownership, appropriate governance, and user feedback. This review does not yet support a Basic / Intermediate / Advanced maturity grade.

Implementation and access decisions remain subject to ICICI Bank’s approved governance and change-management processes.
