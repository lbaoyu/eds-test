The approach

Supervised waves from curated, owned OneDrive folders

AEM Assets has a built-in Bulk Import that pulls content directly from Microsoft OneDrive. It’s fast and needs no custom code, but it works in a specific way: it reads one person’s OneDrive, one top-level folder at a time, and copies that folder’s structure into AEM exactly as it finds it. The approach is designed around that behavior.

Treat the migration as a series of waves. Each wave is one curated OneDrive folder, imported into one place in AEM, and proven on a small pilot before it scales.

4 gates before any production wave: connect, preview, pilot, sign-off
Principle 1

Curate before you move

Bulk Import copies everything as-is: structure, names, and clutter. It’s faster and safer to clean up and organize in OneDrive first than to fix things in AEM afterward.

Principle 2

Prove it small, then scale

A connection check, a preview run that imports nothing, and a pilot of about 150 assets catch almost every problem before it reaches the production library.

Principle 3

Decide ownership upfront

Access runs through one named Microsoft 365 account, and approving an asset makes it publicly deliverable. Both need a named owner from day one.

Fit check

Is OneDrive the right source for this content?

OneDrive works well for planned, supervised migrations. It’s the wrong tool for an always-on feed that nobody watches. Answer this before any other decision.

Use · OneDrive

OneDrive is a good fit when…

  • One accountable ownerThe content already sits in a OneDrive that one person or one dedicated account owns.
  • Planned, supervised wavesThe migration runs in scheduled steps with someone watching, or an agency drop folder is curated by a named admin.
  • Speed over infrastructureSetting up separate cloud storage would delay the project more than OneDrive’s limits cost.
Choose another route · cloud storage

Stage in Azure or AWS storage when…

  • It must run unattendedOneDrive access always runs as a named person’s account, so it can’t act as a background service. Adobe recommends Azure or AWS storage for unattended imports.
  • The content lives in SharePoint or shared foldersOnly the connected account’s own files can be read, and SharePoint isn’t a supported source. That content has to be copied first.
  • Identity policies are strictFrequent password, sign-in, or security policy changes would keep interrupting access that’s tied to one person.

Who’s involved

Four roles, each with a clear decision

How it runs

Six phases from connection to business as usual

Timings are illustrative for a library of about 20,000 assets. Your pilot shows the real pace, so plan the rest of the timeline after it.

01Days 1–2

Connect

IT registers a secure connection between Microsoft 365 and AEM and approves its access to the migration account’s OneDrive.

OutcomeAEM can reach the migration account’s files.
Lead: IT admin
02Week 1

Curate & stage

Remove obsolete and duplicate files, rename them to the naming standard, and arrange each wave folder exactly the way it should look in AEM.

OutcomeClean, wave-sized folders that need no renaming.
Lead: migration owner + DAM lead
03Week 1

Describe

Prepare titles, tags, usage rights, and expiry dates in a spreadsheet, so assets arrive searchable and governed rather than as bare files.

OutcomeA metadata sheet for each wave.
Lead: DAM lead
04Week 2

Validate

Run a connection check, then a preview run that imports nothing, then a pilot of about 150 assets, first on a test environment and then in production.

OutcomePilot signed off against agreed criteria.
Lead: AEM admin + DAM lead
05Weeks 2–3

Execute

Run one wave at a time and move large video and design files overnight. Freeze content in each wave folder, and do a final catch-up run before go-live.

OutcomeThe full library is live and searchable in AEM.
Lead: AEM admin
06Week 3+

Hand over

Retire the OneDrive copies after sign-off. Optionally, set up a scheduled intake folder where agencies can drop new work.

OutcomeBusiness as usual, with named owners.
Lead: DAM lead

Decisions to make

Six decisions to agree before the first import

Each one is cheap to settle in a planning meeting and expensive to change halfway through. Each card includes the recommended default.

Decision 1 · Route

Supervised migration or unattended feed?

OneDrive access is tied to a person’s account, so it pauses whenever that account’s sign-in changes.

RecommendedUse OneDrive for supervised waves and curated drop folders. Use Azure or AWS storage for anything that must run with nobody watching.
Decision 2 · Account

Whose OneDrive holds the content?

Only files owned by the connected account are read. Shared folders and SharePoint sites aren’t.

RecommendedA dedicated, named migration account, not an employee’s personal drive, so access survives staff changes.
Decision 3 · Existing assets

What happens if an asset is already in AEM?

Imports can skip existing assets, add a new version, or overwrite them.

RecommendedSkip by default, so re-running a wave only adds what’s missing. Use new versions to refresh assets already in use. Overwrite only to fix a bad load.
Decision 4 · Source copy

Keep or delete the OneDrive copy after import?

Imports can delete each file from OneDrive once it’s safely in AEM.

RecommendedKeep the copy during the migration as your rollback. Turn on automatic deletion only for recurring intake folders.
Decision 5 · Approval

Should assets be approved on arrival?

With Dynamic Media with OpenAPI, an approved asset can be delivered publicly right away. Approval is effectively publishing.

RecommendedAuto-approve only content that’s already cleared, such as brand logos. Everything else goes through the normal review in AEM.
Decision 6 · Sequencing

One big import or several waves?

A single large import is harder to check, harder to pause, and more likely to be slowed by Microsoft’s rate limits.

RecommendedRun waves in dependency order: brand foundation, then products, then campaigns. Move heavy files overnight.

Risks & mitigations

What typically goes wrong, and how the approach prevents it

RiskWhat it looks likeMitigation
Access tied to one personImports stop after a password reset or a sign-in policy change, or when the account owner leavesA dedicated migration account, a named owner, and a reminder for the yearly renewal
Names change on the way inFolder names become lowercase with hyphens; some special characters get encodedRename to the naming standard in OneDrive first. A pre-flight check flags anything AEM would change
Duplicates and clutterThe same image ends up in several folders; obsolete files arrive with the restCurate before staging. The pre-flight check also flags duplicate file names
Metadata doesn’t landAssets arrive without titles, tags, or rightsVerify metadata on the pilot. If needed, apply the same spreadsheet after import, so no work is lost
Approval means publicationUnreviewed assets become publicly deliverableAuto-approve only cleared folders; everything else goes through normal review
Slow or throttled wavesLarge waves slow down or pause because of Microsoft rate limitsSmaller waves, heavy files overnight, and safe re-runs that pick up where they stopped
Content changes mid-waveCounts don’t match the plan; late files are missedA content freeze for each wave, plus a catch-up run before go-live
