The central idea

The file shows the content. Metadata explains it.

Asset metadata is information attached to an image, video, document, or other content file. It explains what the asset is, what it is for, how it relates to other content, and where it may be used.

Adobe Experience Manager (AEM) Assets is a digital asset management (DAM) platform. It stores files and their metadata so people can find and reuse content without having to reconstruct its context.

The file

What you can see

A photograph shows two travelers at a waterfront. Its filename is DSC_4821.jpg. Neither tells you which campaign commissioned it or which uses the license permits.

The metadata

What you need to know

Title: Waterfront travelers. Campaign: Regional Escape. Owner: APAC Brand Team. Licensed use: owned websites in Singapore and Hong Kong, through December 2026.

The asset is the content.
Metadata is its usable context.

Think of metadata as an asset passport: a record that helps someone unfamiliar with the original project understand the content. Search, forms, workflows, and integrations use different parts of that record.

A field value and a system action are different things. Writing “restricted” describes a condition; an access rule must be configured to act on it. Writing “approved” records a status; it does not explain which version or use was reviewed.

The asset passport

Four kinds of information answer different questions

Adobe’s guidance groups metadata into technical, informational (descriptive), and administrative categories. Here, relationships is an additional explanatory lens: it makes the connections between content records easier to see. These are not four mandatory tabs in AEM. A metadata form can arrange fields to suit its users.

KindQuestion it answersSample values for one photograph
TechnicalWhat kind of file is it? Will it fit?JPEG; 6000 × 4000 pixels; landscape orientation
DescriptiveWhat does it show or mean?Title: Waterfront travelers. Description: Two travelers with daypacks at a waterfront lookout. Subjects: travel, outdoors
AdministrativeWho owns it? What use is permitted?Owner: APAC Brand Team. License reference: LIC-208. Paid social permitted in Singapore only
RelationshipsWhat is it connected to?Campaign: CMP-041. Master asset: AST-004281. Hong Kong copy-overlay version derived from that master

The filename, title, and asset ID do different jobs

DSC_4821.jpg is a filename. Waterfront travelers is a readable title. AST-004281 is an illustrative stable asset ID. The title may change to improve clarity, and the file may move folders, without becoming a different managed asset. Stable IDs let other records keep referring to the same asset.

Not all metadata travels inside the file

A camera can embed capture details in Exif metadata. XMP (Extensible Metadata Platform) can carry fields such as a title or copyright notice. AEM can extract supported embedded values, while storing other information in the managed asset record.

For example, a downloaded JPEG may retain a copyright notice but not an AEM review history or a link to its campaign. A resized rendition does not necessarily carry every metadata field either. The file and the DAM record are related, but they are not the same container.

An asset, a version, a rendition, and a derivative are different

ConceptMental modelExample
AssetThe managed content record with its identity and associated informationMaster photograph AST-004281
VersionA recorded state of the same asset at a point in timeA corrected master is recorded as v4; v3 remains an earlier state
RenditionAn alternative technical representation of the assetA thumbnail or 1200-pixel-wide web image generated from the master
Derivative / variantAdapted creative content whose relationship to its source mattersA separately managed Hong Kong image with Traditional Chinese copy added

Creating a rendition does not, by itself, create a new asset version. A separately managed derivative has its own record, but still depends on the source content’s rights. “Derivative” and “variant” describe creative relationships here, not a guarantee that AEM automatically creates or maintains those links.

How AEM represents metadata

The property is the answer. The form is the question.

AEM stores metadata as properties associated with an asset. A schema or form determines which fields a person sees, how they are labeled, and which property each field reads or writes.

Illustrative field-to-property mapping
Field on the screenStored propertyStored value
Titledc:titleWaterfront travelers
Campaign IDcsc:campaignIdCMP-041
Intended marketscsc:intendedMarketsSG, HK

dc:title is a standard property. The csc: properties are custom examples, not built-in Adobe fields. A real implementation needs its own registered namespace and property mappings.

Different views can show the same answer differently

Admin view uses metadata schemas. Assets view uses metadata forms. Where fields map to the same underlying property, changes to its value are shared between those views. Their form layouts are separate: changing a tab or field arrangement in one does not automatically change the other.

Content Hub, the distribution experience for finding and using assets, separately configures which fields appear on cards, in details, in search, and as filters. A field can therefore be stored correctly in AEM without being visible as a Content Hub filter.

Example: The campaign value is CMP-041 in the asset record. Admin view shows it under “Campaign”; Assets view shows it under “Business context”; Content Hub displays it in asset details. Three presentations, one underlying value where the mappings agree.

A metadata profile supplies defaults

A profile applies default values to subsequently uploaded assets in a folder. Suppose the folder for a particular brand has a profile that sets Brand = Travel A. New assets uploaded there receive that default. Subfolders inherit the profile unless another is assigned.

Changing the profile to another value does not rewrite existing assets automatically. Reprocessing is a separate action and can overwrite existing values. A profile is an intake stamp, not a live relationship that continuously keeps every asset aligned with the folder.

One asset can appear in many organizational views

A folder locates the asset in the repository. Metadata describes overlapping dimensions such as campaign, subject, and intended market. A collection groups references to assets, including assets from different folders, without making duplicate files.

One managed photograph: AST-004281
Folder:      /travel/regional-escape/
Metadata:    Campaign = CMP-041; Subject = Sightseeing
Collections: Regional Escape campaign; Outdoor travel shortlist

Two collection references, not two copies of the photograph.

A static collection contains a chosen set of references. A smart collection uses search criteria, so its membership changes as assets match or stop matching those criteria. These are AEM collection concepts; availability and behavior in other views, including Content Hub, are separate.

Understanding field design

Different questions need different fields

A useful field has one clear meaning. Its value can be plain text, a date, a number, or one or more approved choices. The shape matters because people and systems need to interpret the answer consistently.

Sample fields, not a preconfigured AEM schema
FieldSample valueWhy this shape fits
DescriptionTwo travelers with daypacks at a waterfront lookoutFree text explains a scene more naturally than a long list of categories
Campaign IDCMP-041A single stable identifier connects the asset to a campaign record
Intended marketsSG, HKMultiple approved values represent more than one intended market
License end dateDecember 31, 2026A date can be compared with a proposed use date; exact timing comes from the rights record
OwnerAPAC Brand TeamAn accountable team gives people a route to resolve questions

Intended use is not permitted use

The campaign may target Singapore and Hong Kong, while a photograph’s paid-social license covers only Singapore. A field called simply “Market” hides that difference. Intended markets describes the plan; licensed territories describes permission.

Rights can also depend on combinations. “Territories: SG, HK” plus “Channels: web, social” could wrongly imply that all four combinations are allowed. If social is licensed only in SG, the record needs to preserve that pairing, for example through a linked rights record containing a territory-by-channel table.

“Unknown” is not “unrestricted”

An empty license field means the answer is missing, not that every use is allowed. “No expiry” should mean that the applicable rights genuinely have no end date; it should not mean nobody entered one. Likewise, “not applicable” can be a valid answer for a talent release on a product render with no people.

A form can ask only the relevant questions

Assets view supports cascading rules: a choice can affect which fields are shown, required, or available. For example, Source = licensed stock can reveal a license-reference field, while Source = internal product render can show a product-ID field. This makes the form easier to understand without forcing every asset to answer every question. Form rules do not automatically validate every API or connector update.

Tags and vocabulary

Consistent choices and rich descriptions work together

A controlled vocabulary is an approved list of values. A taxonomy organizes concepts and their relationships, often as broader and narrower categories. These make classification consistent; descriptions add detail that the categories do not capture.

The taxonomy groups the asset with sightseeing content. The description distinguishes this image from a museum visit or a city walking tour. Neither needs to contain the other’s entire vocabulary.

Tags, keywords, and business fields are not interchangeable

Assets view distinguishes taxonomy-backed tags from free-form keywords. A business field such as Campaign ID answers a different question again. The exact underlying mappings depend on the view or integration; “tags” is not one universal property name.

Language and market are also separate. A Traditional Chinese overlay may have locale zh-HK, intended market HK, and a license limited to owned web. Its language does not grant permission for another market or channel.

Where values come from

Extract facts, transfer context, infer descriptions

Metadata is not all entered by hand. Different sources supply different answers, with different levels of certainty.

How the value arrivesExampleWhat it can establish
File extractionAEM reads image dimensions: 6000 × 4000A technical property of the file, not its business purpose
System transferWorkfront campaign field supplies CMP-041Context recorded upstream, if the mapping transfers the correct value
Profile defaultA brand intake folder sets Brand = Travel AAn assumed shared value, which may not fit an exception
Human entry or reviewA rights steward records paid social in SG onlyA business fact grounded in the applicable license
AI inferenceThe image receives “travelers,” “waterfront,” and a generated descriptionA proposed interpretation of visible content, not evidence of permission

What AEM’s AI metadata capabilities do

Smart tags describe recognizable content with machine-generated labels. AI-generated metadata can produce titles, descriptions, and keywords for supported images. Brand Aware Metadata (BAM), a beta capability, can generate custom field values using prompts, referenced metadata, and approved vocabulary. These capabilities have different configuration and availability requirements.

Reasonable inference

Describe the visible scene

“Two travelers wearing daypacks stand at a waterfront lookout.” This can help someone find the image, subject to review of the generated description.

Unsupported inference

Invent the business answer

“Approved for Hong Kong paid social.” The image does not reveal the license, campaign approval, or territory-by-channel conditions.

A sample description prompt

Describe the visible content for asset discovery in one sentence.
Mention the main subject, action, and setting.
Use an approved product name only when supplied as context.
Do not invent a location, campaign, product ID, or license condition.
Do not infer consent or approval.

Illustrative prompt, not a guarantee of correct output. BAM’s documented generation evaluates images and can overwrite existing target-field values; it is not an automatic “fill blanks only” operation.

One asset can contain both facts and suggestions. Its dimensions may be extracted, its campaign copied from a planning record, its rights entered from a license, and its description proposed by AI. An accurate value in one field does not validate the others.

A value is a claim with a source

Provenance means where an answer came from and how it reached the record. Authority means which source or person is entitled to establish that answer. Verification checks whether the recorded answer agrees with the relevant evidence. These are related, but different: knowing that AI generated a value explains its origin, not its correctness.

Recorded claimSource and authorityWhat verifies it
Campaign = CMP-041The approved planning record owns campaign identity; the integration transfers itThe value and source reference agree with that planning record
Paid social permitted in SGLicense LIC-208 supplies the terms; the rights steward interprets and records the scopeThe applicable territory, channel, dates, and restrictions match the evidence
Subject = travelersAI proposes the label; a reviewer can confirm or correct itThe label accurately describes the visible content

Several systems may hold copies of the campaign value, but those copies are not separate authorities. Likewise, a DAM owner can resolve questions about the asset without necessarily having authority to change its license terms.

Populated, correct, and current are different qualities

A field can contain a value and still be wrong or out of date. Metadata describes an asset in a changing business context, not a label completed once and trusted forever.

ChangeWhat becomes uncertainWhat the record needs to distinguish
The master changes from v3 to v4Whether the earlier review still covers the changed contentApproval of v3 versus approval of v4
The license is renewedWhich uses and dates the new terms permitThe earlier license evidence versus the renewed scope
The campaign plan changes upstreamWhether AEM’s copied campaign context has been updatedA transferred snapshot versus a value kept current by configured updates

Inheritance, copying, and synchronization are not synonyms. A profile supplies defaults; a transfer copies values at a defined event; synchronization keeps values aligned according to configured update rules. None should be assumed merely because two records are related.

How metadata helps search

Descriptions find candidates. Structured fields narrow them.

Text and meaning-based search help answer “Does this look relevant?” Structured filters answer more precise questions, such as “Does it belong to this campaign?” or “Is it intended for this market?” Neither by itself proves that the planned use is licensed.

The scene description helps retrieve the waterfront photograph. Campaign, market, and format values narrow the results. The linked rights record answers the final use question.

Why filter combinations change the result

Content Hub uses OR within a filter and AND across different filters. Selecting Singapore and Hong Kong in the market filter means either market can match. Adding JPEG in the format filter means the asset must also be a JPEG.

Intended market: Singapore OR Hong Kong

File format: JPEG

Singapore JPEG       → matches
Hong Kong JPEG       → matches
Singapore video      → does not match
Thailand-only JPEG   → does not match

Metadata must be exposed and configured for the relevant search experience. A custom field stored in AEM does not automatically become a filter in every view. Natural-language discovery can make questions easier to ask, but it cannot supply a missing campaign ID or license.

Rights, approval, and access

“I can download it” is not “I may use it anywhere.”

Four separate questions are often compressed into a single “approved” label. Keeping them distinct explains why an accessible asset can still be unsuitable for a particular use.

QuestionWhat answers itExample
Can this user access it?Permissions and configured access rulesThe APAC Brand Team can retrieve the image
Has this content passed review?Approval of a defined version and scopeRevision v3 passed brand review; a new copy overlay has not
Is this planned use permitted?Rights evidence, territory, channel, dates, and restrictionsHong Kong owned web is permitted; Hong Kong paid social is not
Where should it be distributed?Approval target and delivery configurationThe asset is available in Content Hub, not necessarily at a public delivery endpoint

Metadata can be an input to access rules

Content Hub supports attribute-based access control (ABAC): configured group rules can use asset metadata, such as brand or region. For example, a rule may make Brand A assets available to a particular group. The rule performs the control; the Brand field supplies an input. Content Hub rules do not automatically replace AEM repository permissions or delivery-service controls.

Expiry changes eligibility, not the past

A license end date tells you when the permitted period ends. Expiration behavior depends on the system: Content Hub hides expired assets by default, but administrators can allow viewing or downloading them. A date change cannot retrieve a JPEG already downloaded and uploaded elsewhere.

Example: A marketer downloads the image in December and schedules an ad for January. Having the file is not enough: the January use falls outside a license ending in December.

Metadata across the content supply chain

The context should survive the handoff.

The content supply chain connects planning, creation, review, asset management, and delivery. Each stage knows something different about the content. Metadata carries the relevant answers forward rather than asking the next team to guess.

01Plan

The brief establishes campaign CMP-041, intended markets SG and HK, and the responsible team.

02Create

The photographer supplies the image and license. The file carries its technical properties.

03Review

Review records identify the version checked and the permitted uses, not just a generic approval label.

04Manage in AEM

The asset record brings together the file, campaign reference, descriptions, rights references, and related versions.

05Find and reuse

A marketer finds the image in Content Hub and reads its context before choosing a use.

06Deliver

The selected version is used in a particular website or ad, with a relationship back to its source asset.

AEM does not need to become the original owner of every fact. Workfront may own planning context, a legal record may own license terms, and AEM owns the managed asset record. Copies or references bring the necessary information together.

Mapping transfers values, not just labels

Illustrative Workfront → AEM mapping
Workfront field: Campaign ID
Source value:   CMP-041
AEM property:   csc:campaignId
AEM form label: Campaign

Result: AEM users see CMP-041 on the managed asset.

The native Workfront metadata mapping is one-way toward AEM; it is not automatically a two-way synchronization of every edit. Matching property mappings let AEM forms display the transferred values.

Similarly, GenStudio for Performance Marketing can use connected AEM Content Hub repositories as read-only sources. New assets and updates save in GenStudio; the connection does not by itself write them back into AEM. This is why a file’s origin and its derivative relationships remain important across tools.

The relationship model continues into actual uses

A source relationship answers “What was this made from?” A usage relationship answers “Where was this used?” Together they connect the managed asset to an experience without treating every downloaded copy as a known deployment.

Illustrative relationships
Master photograph AST-004281, v3
  → Hong Kong copy-overlay asset AST-004399, v1
    → Website placement WEB-HK-072
      → Analytics observations for that placement and time period

If the source license changes, those links help identify the derivative and placement whose use needs review. If the website performs well, the same links help relate its results to the content used there. The placement IDs and analytics links in this example must be captured by the relevant systems or integrations; AEM does not automatically know every external use.

Metadata supplies the links; analytics supplies the results. The photograph does not have one intrinsic conversion rate. Results belong to a particular placement, audience, channel, and time period. A download shows retrieval, not deployment or conversion.

Use case A · Find the right content without duplicating it

Request: “Find landscape images of travelers near water for the Hong Kong campaign website.” The scene description finds candidates; the campaign, intended market, and format narrow them. The master is relevant, but its rights still need to match the actual use.

Discovery question
Description / meaning: travelers near water
Campaign:              CMP-041
Intended market:       HK
Format:                JPEG
Orientation:           Landscape

Candidate: AST-004281 v3
Use question: HK + owned web + November 2026 + reviewed v3
Answer: Within the stated license and review scope.

The photograph remains in its campaign folder. A campaign collection and an outdoor-travel shortlist can both reference it. Adding it to the shortlist does not create a second asset, expand its license, or approve it for a new use.

Model in action: Location, classification, collection membership, and permission are four different answers—not four reasons to copy the file.

Use case B · Adapt the size without confusing rendition and version

Request: “The website needs a 1200-pixel-wide image, not the 6000-pixel master.” A resized representation can serve that technical need without becoming a separately managed creative asset.

Master v3AST-004281; JPEG; 6000 × 4000The reviewed source content and its managed identity

Technical suitability is use-specific. A large landscape image may fit a website hero while composing poorly for a vertical ad. Metadata can identify the dimensions; it cannot replace inspecting the resulting composition.

Use case D · Combine assets into a video

Request: “Use the photograph in a 15-second Singapore paid-social video.” Assume LIC-208 explicitly permits this adaptation in SG paid social, and the music record permits that same use through November 30. The finished video has its own technical properties, captions, and review.

Sample video record
Asset:          AST-004500 v2
Campaign:       CMP-041
Format:         MP4 · 1080 × 1920 · 15 seconds
Caption locale: en-SG
Components:     AST-004281 v3; MUS-012
Review:         REV-044 approves v2 for the specified SG paid-social use
Image rights:   LIC-208 · permitted through December 31

The proposed use must satisfy all relevant component permissions, not just the photograph’s license. A December campaign would exceed the music period even though the image period continues. A Hong Kong paid-social placement fails the image’s scope regardless of the video’s intended markets.

The finished video’s license conditions cannot be summarized safely by copying the most generous end date from one component. Component references preserve the evidence behind the combined answer. Rights aggregation is a reasoning model here, not a claim that AEM automatically calculates it.

Request: “The description names the waterfront as Hong Kong. Can we publish that location?” The photograph’s intended-market value does not establish where it was captured.

The corrected description can remain “Two travelers at a waterfront lookout.” Similarly, Review = approved is not sufficient if no record identifies the approved version and scope. A populated field can still be incomplete for the question being asked.

Use case G · Understand what happens when records change

Request: “We have a new master and updated rights. Does everything connected to it become current?” Relationships help explain dependencies, but do not imply automatic inheritance or synchronization.

Metadata needs to distinguish which fact changed, which record owns that fact, and which related answers depend on it. That is why “current” is more meaningful than merely “filled in.”

Use case H · Trace distribution and results back to the source

Request: “Where is the photograph used, and which result belongs to which content?” Assume configured integrations have captured the following references.

AST-004281 v3 · master photograph
  → AST-004399 v1 · reviewed HK copy-overlay derivative
    → WEB-HK-072 · owned website placement
  → AST-004500 v2 · video with music MUS-012
    → AD-SG-091 · paid-social placement

Analytics observations are linked to WEB-HK-072 or AD-SG-091,
with their audience, channel, dates, and metric definitions.

A license question can follow these links to the affected uses. A performance question can follow them to the measured placements. AEM does not discover every external use merely because someone downloaded the asset, and a GenStudio-created output does not automatically appear back in AEM without a return flow.

If the website and ad perform differently, that is not evidence that the master photograph has two contradictory “scores.” They are different experiences, with different copy, formats, audiences, and distribution. Metadata connects those observations to content; it does not isolate the photograph as the cause.

A user may also have access to the campaign pack without permission to publish every item. Access rules, version-specific review, use-specific rights, and delivery configuration remain distinct throughout these examples.

Metadata does not make every use valid.
It makes the differences understandable.
