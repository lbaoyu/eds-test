How it works

One user’s drive, one root folder, one target path

OneDrive Bulk Import doesn’t sync anything. It’s a pull job: it signs in as a named Microsoft 365 user, walks one root folder in that user’s OneDrive, and recreates the folder tree under one AEM target path. Along the way it applies AEM’s naming rules, your folder profiles, and an optional metadata CSV. Everything in this runbook follows from that model.

Treat every import as a wave: one OneDrive root folder → one configuration → one AEM target. Prove it on 150 assets before you move 15,000.

Fit check — is OneDrive the right source?

Use · OneDrive

OneDrive is a good fit when…

  • One accountable ownerThe content already lives in a OneDrive that one person (or one dedicated account) owns.
  • Supervised wavesMigrations run as planned waves, or a drop zone is curated by a named admin.
  • No cloud bucket on handStanding up Azure Blob or S3 would delay the project more than the OneDrive constraints cost.
Stage elsewhere · Azure Blob / Amazon S3

Copy to Azure Blob or S3 first when…

  • It must run unattendedOneDrive supports delegated (user) OAuth only — no app-only or service-principal auth. Adobe recommends Azure Blob or S3 for unattended imports.
  • The source is SharePoint or “Shared with me”The connector reads only the signed-in user’s own drive. Bulk Import has no SharePoint source.
  • Identity policy is strictMFA re-registration, Conditional Access, and password rotation will keep breaking a token tied to one user.

Before you start

Four roles, one worksheet

Most failed first runs are coordination failures. The person who registered the app isn’t the person whose OneDrive holds the files, or the target folders don’t have profiles yet. Line up the four roles and fill in the worksheet before anyone opens Bulk Import.

Role A · Step 03

Entra / Microsoft 365 admin

Registers the app, adds the delegated Graph permissions, grants admin consent if user consent is blocked, and owns secret rotation.

Role B · Steps 04, 06

Migration user

The licensed OneDrive account that owns every wave folder and signs in during setup. Use a dedicated named account, not someone’s personal drive.

Role C · Steps 06–08

AEM Assets administrator

Creates, checks, dry-runs, runs, and schedules configurations in Assets view. Bulk Import is limited to administrators.

Role D · Steps 04–07

DAM architect / DM admin

Pre-creates target folders, metadata and Smart Crop profiles, and tags. Decides how assets get approved for Dynamic Media with OpenAPI, then signs off the pilot.

    The URI must match exactly: no trailing slash, no path.

    Platform
    Web

  3. Copy the two IDs

    On the app’s Overview page, copy Application (client) ID and Directory (tenant) ID into the worksheet.

  4. Add delegated Microsoft Graph permissions

    API permissions › Add a permission › Microsoft Graph › Delegated permissions, then Add permissions. If tenant policy blocks user consent, click Grant admin consent for <tenant>.

    OpenId permissions
    offline_access — refresh tokens, so runs don’t need a new sign-in each time
    Files
    Files.ReadWrite.All — read files; write is needed for Delete source file after import

  5. Create the client secret and copy its Value

    Certificates & secrets › Client secrets › New client secret. Copy the Value column right away. It’s shown only once. AEM doesn’t use the Secret ID.

    Description
    aem-bulk-import-2026-11
    Expires
    12 months — and add a reminder 30 days before expiry
Why ReadWrite, not Read? The write scope only powers source deletion

Bulk Import offers Delete source file after import, which needs write access. The permission is delegated, so it never goes beyond what the migration user can already change in their own drive. AEM never writes assets back to OneDrive.

Don’t Don’t switch to Application permissions

OneDrive Bulk Import supports delegated (user) OAuth only. App-only and service-principal setups aren’t supported, so don’t try to engineer around a user sign-in. For fully unattended feeds, stage in Azure Blob or S3.

Prefer scripting? Azure CLI equivalent

Does the same as steps 1–5. The permission GUIDs are Microsoft Graph’s published IDs for delegated offline_access and Files.ReadWrite.All.

Step 2 · OneDrive

Stage OneDrive so AEM has nothing to rename

Bulk Import copies whatever it finds. The cheapest migration is one where AEM has nothing to rename. Build each wave folder in the shape of your target DAM tree, using names that already follow the folder-structure guide. Then the node names, titles, metadata paths, and the readable names in Dynamic Media URLs all match.

Rule 1 · LocationRoot only

One root-level folder per wave, in the migration user’s My files

Enter the folder name only, never the URL. For https://meridian-my.sharepoint.com/personal/aem-migration_meridian_com/Documents/AEM-Import-Wave01, enter /AEM-Import-Wave01/. Spaces are allowed exactly as written. Nested paths such as /Projects/Wave01/ aren’t supported.

Rule 2 · OwnershipOwn drive

Files must be in the migration user’s own drive

Folders under Shared with me, Teams channels, and SharePoint libraries can’t be read. In the field, a dry run against a shared folder fails with resource not found. Copy the content into the migration user’s drive first. A folder the migration user owns and shares out to an agency works, because it stays in their drive.

Rule 3 · ShapeMirror 1:1

Lay out the wave root exactly like the target tree

Everything under the wave root lands under the target, with the root folder removed. Don’t add a wrapper folder that you’d have to move in AEM later. Moving published assets means unpublishing them first.

Rule 4 · Namesa–z 0–9 - _

Rename in OneDrive, before the import

Use lowercase, hyphenated folders and ASCII file slugs (meridian_autumn-rewards_hero_16x9_v02.jpg). Put localized names (Thai, Chinese, Korean) in dc:title through the CSV, not in the node name.

Rule 5 · Volume≤ 1,000 / folder

Split large leaf folders before import

AEM accepts bigger folders, but above 1,000 direct children the Admin view lists them from an asynchronously updated index, so new items show up with a delay. Split by year, product line, or campaign.

Rule 6 · Dynamic MediaDescriptive slugs

Make file names descriptive and unique

Dynamic Media with OpenAPI addresses assets by UUID (/adobe/assets/urn:aaid:aem:<uuid>/as/<seo-name>.<ext>), so two hero.jpg files don’t collide. But the file name becomes the readable SEO name in the URL and the label in search, and duplicate names across a wave usually mean duplicate uploads. Add brand, campaign, or SKU tokens.

If the same repository also runs Dynamic Media in Scene7 mode, duplicate names do collide: one overwrites the other or gets a -1 suffix. Treat duplicates as blockers there.

Pre-flight audit script

Run it on the OneDrive sync client’s local copy of one wave folder. It’s read-only and works on Files On-Demand placeholders, so nothing gets downloaded. Runs in Windows PowerShell 5.1 and PowerShell 7 on Windows or macOS. It flags every rename, skip, empty folder, oversized folder, and duplicate file name, and writes them to a CSV report.

Step 3 · Metadata

Ship metadata with the binaries

The Metadata File option applies a standard AEM metadata CSV while the wave imports: titles, tags, rights, expiry. Assets arrive searchable instead of waiting for a cleanup sprint. The format is the same one used by Assets metadata import and export.

Header row
assetPath,dc:title {{String}},cq:tags {{String: multi}}
  • Column 1 is assetPath: the final absolute DAM path, not the OneDrive path.
  • property {{Type}}. Property names are case-sensitive; types aren’t. With no type, String is assumed.
  • Multi-value: {{String: multi}}, with values separated by |.
  • Dates: {{Date}} with values like 2027-06-30T23:59:59.000+08:00.
Data rows
/content/dam/meridian/…/hero_16x9_v02.jpg,Autumn hero,a:b|a:c
  • A blank cell leaves the property unchanged. It doesn’t clear an existing value.
  • cq:tags takes tag IDs (meridian:campaign/autumn-rewards). Create the taxonomy first.
  • Register custom namespaces (e.g. meridian:usageRights) before the import.
  • Save as UTF-8 (Excel: CSV UTF-8). Thai, Chinese, and Japanese titles get corrupted in ANSI.

Required Keep the CSV out of the asset load

Put the CSV in the wave root, set Metadata File to /AEM-Import-Wave01/metadata-wave01.csv, and add text/csv to Exclude MIME Type. Otherwise the CSV gets imported as an asset, and if Delete source file is on, it gets deleted from OneDrive.

Field note Prove the metadata on the pilot, and keep a fallback

Before you build the full wave file, check that CSV values appear on 5–10 pilot assets. If they don’t, apply the same CSV after the load from Admin view › Create › Metadata. The format is identical, so none of the work is lost.

Approval means delivery Approving assets through the CSV makes them deliverable as soon as they land

Dynamic Media with OpenAPI only delivers approved assets, so dam:status = approved with dam:activationTarget = delivery is effectively a publish. Use it only on folders whose content is already cleared, such as brand foundation. Adobe doesn’t document the Bulk Import Metadata File as an approval action, so confirm on the pilot that an approved asset’s delivery URL resolves. If it doesn’t, approve in Assets view (multi-select › Approve) or with a folder Metadata Profile.

Generate the CSV from the wave folder

This Python 3 script walks the wave root and refuses to run if any name would be rewritten, so assetPath always matches the real node. It applies folder-level defaults from RULES, writes a UTF-8 CSV into the wave root, and prints the exact Metadata File value. Edit RULES and COLUMNS for your taxonomy, then fine-tune titles in a plain-text editor.

Execution rules

  1. 1
    One wave at a timeRun large imports one after another, not in parallel. Parallel jobs compete for the same processing capacity and make failures harder to trace.
  2. 2
    Heavy files off-peakProcessing (renditions, Smart Crops, video) is the bottleneck, not the transfer. Schedule the Min-size configuration for nights and weekends.
  1. 3
    429 means Microsoft is throttlingA Graph 429 activityLimitReached response is OneDrive-side throttling. The importer backs off and retries. If it keeps happening, the wave is too big: split it.
  2. 4
    Freeze each wave rootEdits made after the Dry Run aren’t in your counts. Announce a freeze per wave and use W04 to pick up late arrivals.
