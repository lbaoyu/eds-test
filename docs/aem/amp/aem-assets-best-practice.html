Upload and ingestion

A five-step ingestion process

This guidance combines the uploaded training deck’s recommendations with Adobe’s current Assets documentation. Prepare, organize, upload, verify, then review before broad reuse.

  1. Prepare the assets before upload

    Confirm the intended use, owner, destination, and required metadata. Remove obvious duplicates and assets AMP does not need. For a SharePoint migration, identify content whose ownership or usage rights are unclear before moving it.

  2. Choose the destination and organize the batch

    Agree on the destination folder structure and metadata schema first. Group assets by a meaningful business purpose—such as campaign, product, or asset type—rather than uploading an unstructured file dump.

  3. Use the right upload path

    Choose a method based on the job (see the next section). For large imports, plan and curate the ingestion, and consider splitting it into manageable batches.

  4. Check the result

    Confirm that expected files arrived, previews and renditions are available, required metadata is present, and users can find sample assets using expected search terms.

  5. Review before broad reuse

    Apply AMP’s review and approval process so users can distinguish drafts from assets approved for reuse.

What AEM does during ingestion

AEM Assets can process uploaded content, extract metadata, generate renditions, and apply Smart Tags. These capabilities help prepare assets for management and discovery, but AMP should still verify that the result meets its standards.

Manual, bulk and automated upload

Pick the method that fits the job

Adobe distinguishes occasional UI uploads, desktop and Creative Cloud workflows, APIs for upload-time decisions, and Bulk Import for large-scale ingestion. The bar shows relative volume and technical effort, from a few files to a designed pipeline.

Assets web interface

Best fit for AMPOccasional uploads or a small number of files where a person can check the destination and metadata as they upload. Avoid using it as the default for very large ingestions.

Adobe Asset Link

Best fit for AMPCreative users who work in supported Creative Cloud desktop applications and need to access or upload assets as part of that workflow.

ExampleA designer saves a deliverable from Photoshop, Illustrator, or InDesign into the DAM workflow.

Bulk Import

Best fit for AMPLarge-volume ingestion, initial population, or migration from a supported cloud-storage source. Plan it as an ingestion project: curate content, organize the source, map metadata, and consider staged batches.

ExampleA planned migration of a selected product-image library from a supported cloud source after cleanup and metadata mapping.

API or custom uploader

Best fit for AMPA recurring or specialized process that needs upload-time logic, such as applying metadata rules, renaming files, or routing assets. This requires technical design and should use an appropriate supported interface.

ExampleA repeatable integration that maps AMP campaign fields into AEM metadata during upload.
Bar: volume and technical effort — low to high
SharePoint migration consideration for AMP

Adobe’s current Bulk Import guidance names cloud sources such as Azure, AWS, Google Cloud, Dropbox, and OneDrive; it does not list SharePoint as a direct Bulk Import source. AMP should confirm the ingestion path before planning the migration. Depending on the source and chosen approach, this may involve staging selected SharePoint content in a supported source or using a separately designed migration integration.

When to consider automation

Use automation when AMP has repeatable rules—such as metadata mapping, routing by asset type, or recurring batch intake—not simply because an upload contains many files. For large imports, pilot a representative sample, review the result, and then proceed in planned batches. This reduces the risk of multiplying a bad folder structure or metadata mapping across the repository.

Findability

Organize for both browsing and search

Use folders for stable placement and navigation; use metadata and tags for finding assets across different contexts. Do not rely on folder names alone to answer every search or governance question.

Folders

Stable placement & navigation
  • One agreed home for each asset
  • Intuitive and reasonably shallow
  • Familiar, consistent names

Metadata & tags

Discovery across contexts
  • Find by product, market, channel, status
  • Approved fields and taxonomy tags
  • Search filters, collections, saved groupings

For example, a campaign asset may belong in one agreed campaign location but be discoverable by product, market, channel, and approval status through metadata or tags.

Practical AMP guidance

  • Keep the hierarchy intuitive and shallow. The deck’s roughly 3–4 levels is a planning guideline, not a product limit; test whether users can place and find representative assets.
  • Use familiar, consistent names. Avoid ambiguous folders such as Misc or repeated Final folders.
  • Search by approved fields. Use metadata, taxonomy tags and filters for campaign, product, market, language, channel, or status where they matter to AMP.
  • Use collections for working sets. Collections or saved, search-based groupings give teams a working set without duplicating assets.
Test the model with real searches

Check whether the expected assets appear and irrelevant or expired items can be filtered out.

  • “approved campaign hero image for [market]”
  • “product image for [campaign]”
Common discoverability problems

Adobe identifies absent metadata or tags, unintuitive folders, inconsistent naming, and duplicate assets. Tags support retrieval and grouping, while collections can support controlled collaboration and reuse.

Metadata

A practical starting structure

Define a small, useful metadata model before a large upload. Use tailored schemas where asset types differ, keep required fields focused on AMP’s actual workflows, and use approved values where consistency matters. Version management

Working revisions versus approved assets

Use versions to track revisions to the same logical asset; use approval status and workflow to indicate whether that asset is ready for broader use.

Version history

Tracks revisions
  • Review prior states of the same asset
  • Restore a prior version if needed
  • Not itself an approval process

Approval

Signals readiness for reuse
  • A checkpoint that identifies the approved, latest version
  • Uploading a newer version does not automatically mean it is approved
  • Must be made explicit for broad reuse
Same deliverable

Continuing revision

Keep it as the same asset and create a new version. Successive edits to the same campaign hero image can remain in that asset’s version history.

Different deliverable

Distinct asset identity

Use a separate asset when content is meaningfully different—a localized version or a separate channel crop—then relate it to the campaign or master using AMP’s agreed metadata or organization.

Work in progress

Controlled working area

Use an approved working area and review process with access suited to the contributors. Avoid final, final2, or final-final as a substitute for version history and approval status.

Interface behavior varies

Version behavior depends on the interface and action. Adobe documents viewing, creating, and restoring versions; in Assets view, uploading a same-named asset to the same folder can prompt the user to overwrite or save it as a version. AMP should train users on the behavior in its chosen interface and test the desired workflow.

Takeaway

Choose the upload method by source, volume and workflow; organize with folders and metadata; and keep versions and approval as two separate controls.
