Move SharePoint assets into AEM Assets through Azure.

How AEM’s Bulk Import uses Azure Blob Storage as a staging area, and why that’s the cleanest route for content that lives in SharePoint today.

The route

Three hops: SharePoint, Azure, AEM Assets

AEM’s Bulk Import collects files from cloud storage, not from collaboration sites, so it can’t read SharePoint directly. The content takes one detour through a private Azure Blob Storage container. Files and their SharePoint column data travel on two separate paths and meet again in AEM.

Think of Azure as a loading dock. Content is copied there once, AEM collects it from there, and the dock is cleared when the move is done.

Why Azure

Six reasons Azure is the cleanest staging area

Bulk Import supports several cloud sources. Azure Blob Storage is the most mature of them, and the natural fit for organizations that already run on Microsoft 365.

Not tied to a person

AEM connects with a storage credential, not an employee’s sign-in. Password resets, MFA changes, and role changes don’t interrupt imports.

Adobe’s recommended route

Adobe recommends Azure (or Amazon S3) for large and scheduled imports.

Works in both interfaces

Admin view (Tools › Assets › Bulk Import) and the newer Assets view run the same engine. Both support Azure, health checks, dry runs, and schedules.

Built for volume

No per-copy size caps or personal storage quotas, and very large files are fine.

Cloud-to-cloud transfer

Files move straight from the container into AEM’s cloud storage, never through a laptop or a browser upload.

Easy to inspect

IT can browse exactly what’s staged with Azure’s own tools before anything is imported.

How an import runs

Five stages, every time

Every import goes through the same stages, whether it’s 50 files or 50,000.

Steps 1–2 change nothing · always run first

Check

Confirms AEM can reach the container, and that the token is valid, unexpired, and has the right permissions.

Dry run

Metadata & approval

How SharePoint columns become AEM metadata

Export the library view to a spreadsheet, map each column to an AEM field, and save it as a CSV next to the staged files. AEM matches each row to its asset by the asset’s final location in AEM.

Approval means delivery With Dynamic Media with OpenAPI, approved assets are deliverable

Only approved assets can be delivered, and an approved asset can be delivered publicly right away. Setting approval through the metadata file is effectively publishing. Reserve it for content that’s already cleared, such as brand logos. Everything else goes through normal review in AEM.

Safety net Metadata can always be applied later

The metadata file uses the same format as AEM’s standard metadata import. If any values don’t land during the import, the same file can be applied again afterward, so none of the mapping work is lost.

Security model

The token is the lock

The container stays private, and AEM gets in only with a shared access signature (SAS) token. That token, not a network rule, controls access.

SAS tokenThe only key AEM is given
Scope
One container: aem-migrationMore reliable than an account-wide token, and limits exposure.
Permissions
ReadListDeleteDelete only if Delete source after import is on.
Expires
Shortly after the planned end of the migration
Revoke early
Rotate the storage account key or remove the token’s access policy. Access stops immediately.
Private container

No public access. Only authorized requests are accepted, so nobody can browse or download the staged files without a valid credential.

No network allow-lists

Bulk Import doesn’t support limiting the storage account to specific networks or IP addresses, because the copy runs between cloud services.

Your region, your subscription

The storage account lives in the Azure region your policies require. Storage and data-transfer charges apply while the container exists.

Admins only in AEM

Only AEM administrators can create or run Bulk Import configurations. The token is stored in the configuration, not shared with users.
