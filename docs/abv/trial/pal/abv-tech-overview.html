Purpose and scope

A clear view of the service boundary

Adobe Brand Visibility combines Adobe workflows with Semrush-powered market intelligence and prompt tracking. It monitors answers produced by supported AI platforms and reports signals such as brand mentions, citations, sentiment, and visibility. See the Adobe Brand Visibility product overview.

Scope note. This overview describes standard capabilities. PAL's enabled integrations, exact configuration, and contractual terms have not been verified here. CDN logs, analytics, Google Search Console, and edge optimization are optional connections; their data flows apply only when enabled.

Monitoring

Configured prompts, not private chat histories

Monitoring is based on prompts configured in the Brand Visibility Prompt Library; it is not described as ingesting PAL users' chat histories. Prompts are run on a recurring basis. See Prompt Management.

Optional connections

PAL controls which integrations to enable

PAL may connect CDN logs, selected analytics data, or Google Search Console, and may choose to configure Optimize at Edge. These are separate from prompt monitoring.

Service components

How the main components fit together

The service spans Adobe Brand Visibility workflows, Semrush-powered capabilities, supported external AI platforms, and any PAL systems connected by choice. The product overview describes the service at a high level.

ComponentRoleBoundary
Adobe Brand Visibility Provides the application experience, Adobe-side workflows, dashboards, and integrations. Managed by Adobe. Public customer documentation reviewed does not specify the hosting location or detailed infrastructure boundary for every Semrush-backed component.
Semrush-powered services Provide AI visibility, prompt research, and prompt-tracking capabilities within the service. Semrush provides the underlying market-intelligence and prompt-tracking capabilities for these features.
External AI platforms Receive monitored prompts and return generated answers for analysis. Operated by their respective providers. Exact payload, retention, and handling terms are not detailed in the customer-facing sources cited here.
PAL systems (optional) May supply CDN access logs, selected analytics data, Search Console data, or CDN configuration for edge optimization. Involvement depends on integrations PAL elects to enable and configure.

Prompt monitoring is performed through the Brand Visibility/Semrush service workflow. It does not require PAL to send prompt requests to AI platforms from PAL's own network.

Information exchange

Data flows depend on enabled capabilities

The table distinguishes the standard prompt-monitoring flow from optional PAL integrations. The specific fields and settings should be checked against PAL's deployment before activation.

FlowInformation involvedWhen it applies
PAL setup → Brand Visibility Brand/domain and configured prompt information, with market or language settings needed for monitoring. Used to configure and run Brand Presence monitoring.
PAL CDN → Adobe Forwarded CDN access logs. Documented fields include URL path and query parameters, user agent, status code, referrer, host, time to first byte, request method, timestamp, and content type. Only if PAL enables CDN log forwarding. Adobe's Agentic Traffic documentation lists the processed fields and states that no PII is processed or stored in this flow. Because URL paths and query parameters are included, PAL should still review and sanitize logs for sensitive values before forwarding.
PAL analytics → Brand Visibility For the Adobe Analytics integration, documented data includes dimensions such as referrer, country, device type, and a selected page dimension, plus metrics such as visits, orders, and revenue. The integration guide says raw hit-level data, query strings, page content, and user identifiers are not ingested. CJA mappings depend on PAL's selected fields; its integration also excludes user identifiers and raw event-level rows. Only if PAL connects Adobe Analytics or Customer Journey Analytics (CJA) and configures the relevant mappings.
Service layer → external AI platforms Configured prompt text is submitted to supported AI platforms for monitoring. Public documentation does not specify the complete provider-by-provider request payload. When configured prompts are run for monitoring.
External AI platforms → service layer Generated answers are analyzed to produce reporting. Public documentation cited here does not detail the complete response payload or provider-specific handling. As part of prompt monitoring and analysis.
Google Search Console → Brand Visibility Data exposed through the connected Search Console integration. Only if PAL elects to connect Google Search Console and grant the required access.

Prompt hygiene. Avoid placing confidential, personal, or regulated information in monitored prompts. Before enabling log forwarding, review URL paths and query parameters for tokens, identifiers, or other values PAL does not intend to share.

Monitoring and analysis

AI answers are analyzed into reporting signals

Brand Visibility does more than retrieve and display answers. It derives reporting signals such as brand mentions, citations, sentiment, position, and aggregate visibility scores from answers produced by external AI platforms.

What is documented

Recurring prompt runs and answer analysis

Prompts in the configured Prompt Library are run on a recurring basis. The resulting answers inform visibility reporting, including brand mentions, citations, sentiment, position, and aggregate visibility signals.

What is not specified

Model-by-model implementation details

The reviewed customer documentation does not identify a separate Adobe foundation model used for every processing step, or explain whether a generative model performs each extraction or classification task.

Supported platform coverage

The published AI Visibility dashboard documentation lists ChatGPT, Google AI Overviews, Google AI Mode, and Gemini. Coverage can vary by feature and configuration. Confirm the currently enabled platform list, including whether Claude is covered for PAL's use case, before relying on specific platform availability.

External AI platforms and their crawlers may also access PAL's publicly available site. Such visits are distinct from prompt execution; CDN log forwarding, if enabled, can help measure agent traffic.

PAL setup and considerations

Review each connection on its own terms

PAL configures its brand/domain and prompt strategy. Other capabilities require additional setup and should be reviewed with the relevant PAL owners before activation.

ConfigurationPractical review point
Prompt Library Prompts are sent to external AI platforms for monitoring. Keep confidential, personal, or regulated information out of prompt text.
CDN log forwarding Review the fields forwarded, particularly URL paths and query parameters, for tokens, identifiers, or other sensitive values.
Analytics connection Limit the selected report suite or data view and mapped fields to what PAL intends to share. The Adobe Analytics integration guide currently states that its data is retained indefinitely and encrypted in transit but not at rest. Have Adobe Security confirm this is current before sharing it as applicable to PAL; do not treat it as a broader service-wide assurance.
CJA connection The CJA integration documentation describes temporary processing in the United States; data is ultimately stored in the region specified by the customer's CJA contract.
Optimize at Edge Requires CDN configuration and changes delivery for AI-agent traffic. Review the Optimize at Edge setup with PAL's CDN team and test before production deployment; the CMS authoring workflow remains unchanged.
External provider handling The sources cited here do not establish provider-specific retention, model-training, or manual-review terms for every Semrush-powered function. Confirm these points through the applicable Adobe security and privacy review before making assurances.
Deployment-specific confirmation

Confirm PAL's enabled integrations, field mappings, data residency requirements, and applicable external-provider terms before implementation. The information above describes documented standard behavior, not a verified PAL environment configuration.
