Core Principle

Folders enforce governance; metadata drives discovery

The single biggest mistake in Digital Asset Management (DAM) implementations is rebuilding a shared network drive—nesting 9 levels of folders to anticipate every way someone might browse for a file. In AEM Assets, folder paths are permanent infrastructure whose primary job is inheritance and operational control.

Treat your folder hierarchy as the structural foundation of the house, and Omnisearch, AI Search, faceted metadata, and Collections as how teams move through it. Store every master asset in one canonical folder and surface it everywhere else dynamically.

1 Asset : 1 Path Zero duplicate files across channel or team folders
Layer A · Storage & Inheritance

What folders should govern

Physical Path

Create a new folder branch only when assets need a distinct setting in at least one of these five inherited AEM mechanics:

  • Access Control Lists (ACLs) Group-based Read, Modify, Create, Delete, and Publish permissions inherited down the subtree.
  • Metadata Schemas & Metadata Profiles Which property form tabs display, plus auto-stamped defaults on upload (Brand, Campaign, Region).
  • Processing, Image & Video Profiles Folder-assigned renditions, Dynamic Media Smart Crop aspect ratios, and video encoding presets.
  • Publication & Dynamic Media Sync Scope Controlling which subtrees sync to Dynamic Media CDN delivery versus staying author-only.
  • Lifecycle Stage Isolation Cleanly separating studio Work-in-Progress (WIP) from approved production libraries and admin archives.
Layer B · Discovery & Curation

What metadata & Collections handle

Virtual Facets

Never split or duplicate folders for dimensions that AEM Assets natively indexes, filters, or groups virtually:

  • File Type, Format & Orientation Omnisearch and Adobe Express Content Advisor include out-of-the-box MIME type, format, and size filters.
  • Multi-Channel Reuse One master image serving web, email, and social stays in one folder—tag channels in metadata and deliver crops via Dynamic Media.
  • Cross-Folder Campaign Kits (Collections) Assemble seasonal kits or agency handoffs across folders using static or Smart Search Collections.
  • Approval Status & DRM Expiration Track Asset Status, Usage Rights, and Expiration Date in metadata instead of moving files daily.
  • AI Search & Brief Matching Content Advisor AI Search in Express resolves multilingual intent, synonyms, and uploaded campaign briefs via metadata.

Repository Guardrails

Six technical rules for scalable JCR hierarchies

Under the hood, AEM Assets stores folders and assets as nodes inside Apache Jackrabbit Oak (JCR). Designing within these six technical boundaries keeps the Author UI fast, simplifies permission audits, and prevents broken CDN links.

Rule 01 · Depth 3–5 Levels Max

Keep folder hierarchies shallow under /content/dam/<org>

Structure paths as /org/domain/category/leaf. Shallow hierarchies make upload destinations unmistakable for contributors and keep folder breadcrumbs readable inside Adobe Express.

Why it matters: Deep 8–10 level trees hide inherited ACL overrides and bloat delivery URLs.

Rule 02 · Density ≤500–1,000 Assets

Cap direct child assets per leaf folder at 1,000

Partition growing branches predictably (by year, product line, or campaign) before any single folder exceeds 1,000 files. While AEM as a Cloud Service scales higher than AEM 6.5, keeping leaf counts under 1,000 preserves instant card/list rendering.

Why it matters: Multi-thousand-node folders slow UI scrolling, bulk metadata edits, and browser memory.

Rule 03 · Placement Leaf Nodes Only

Store asset binaries only in terminal leaf folders

Keep Level 1 and Level 2 folders purely structural (holding subfolders only) and upload actual files into the lowest leaf folder of each branch.

Why it matters: Mixing hundreds of loose files alongside subfolders degrades AEM UI tree loading and muddies profile inheritance.

Rule 04 · Node Type sling:Folder

Use unordered folders over sling:OrderedFolder

Always create standard unordered sling:Folder nodes (the AEM Assets default) in API scripts and migration packages rather than sling:OrderedFolder.

Why it matters: Oak tracks ordered child nodes in a single parent array property, causing write contention under concurrent uploads.

Rule 05 · Moves Unpublish First

Unpublish folders or assets before moving, renaming, or archiving

Treat JCR folder slugs as permanent system paths once live. Whenever restructuring or retiring content, unpublish the subtree from AEM Publish and Dynamic Media before moving it.

Why it matters: Moving published paths directly leaves orphaned, unreachable “stranded assets” live on Publish/CDN tiers.

Rule 06 · Geography Locale at the Leaf

Put global domains at the top and regional adaptations at the leaf

Avoid starting the DAM with /apac, /emea, and /americas at Level 1 unless strict legal residency mandates total isolation. Nest locale folders underneath the shared product or campaign instead.

Why it matters: Top-level regional folders wall off teams into silos and trigger duplicate uploads of the same global photography.

Naming Standards

Decouple human titles from immutable JCR node slugs

Every AEM folder stores two separate values: a business-friendly Folder Title shown in cards and breadcrumbs, and a machine-safe Node Name used in JCR paths and delivery URLs. Keep titles readable while locking down strict slug and filename rules.

1 · UI Display Property (jcr:title)
Autumn Rewards — APAC (2026)
  • Human-friendly: Title case, spaces, and readable labels for business authors and Express users.
  • Safe to refine: Updating jcr:title later does not change the underlying repository path or break published links.
  • Consistent grammar: Choose plural nouns for containers (Campaigns, Products, Logos) and omit redundant words like “Folder”.
2 · JCR System Path Slug (Node Name)
autumn-rewards-apac-2026
  • Strict slug syntax: Lowercase ASCII letters, digits, and hyphens only (spaces in folder titles auto-convert to - on creation).
  • Treat as immutable: Never rename live node slugs without unpublishing first.
  • Sortable ISO prefixes: Use YYYY or YYYY-MM (2026-09) and ISO locale codes (en-sg, zh-hk) for chronological sorting.
Disallowed AEM Assets filename characters: * / : [ \ ] | # % { } ? & Also avoid spaces, accents, and punctuation (! @ $ ^ + = ~ ,) to prevent URL percent-encoding bugs across CDNs.

Recommended Asset Filename Formula

Target 50–75 chars · Critical info in first 100 chars (Dynamic Media)
[brand]meridian - [domain-or-campaign]autumn26 - [subject-descriptor]platinum-card-couple - [aspect-or-variant]hero-16x9 - [locale]en-sg . [ext]jpg
Compiled result (56 chars): meridian-autumn26-platinum-card-couple-hero-16x9-en-sg.jpg Upload revisions as a new AEM Version of the same file—never _FINAL_v2_REAL.jpg.

Dynamic Media

4 folder rules for clean CDN delivery

  1. 1
    Enforce globally unique filenames across all folders Dynamic Media (Scene7) uses a flat global Asset ID rather than the JCR folder path. Two files named banner.jpg in separate folders overwrite one another or generate -1 / -2 URL suffixes.
  2. 2
    Never match a Level-1 folder name to the DM Company name Keep root /content/dam/<folder> slugs distinct from your Dynamic Media Company alias, and assign a dedicated DM Company per AEM environment (Dev/Stage/Prod) to prevent shared Smart Crop link collisions.
  3. 3
    Scope Dynamic Media sync mode per folder branch Uncheck global Sync all content so you can set Enable for subfolders on master libraries and Disabled for subfolders on /wip-studio and /archive.
  4. 4
    Group folders by Smart Crop & Selective Publish needs Image and Video Profiles attach at the folder level: separate /products (1:1, 4:5 PDP crops) from /campaigns (16:9, 9:16 hero crops), and use On Activation or Selective Publish so drafts are not live on public URLs prematurely.
Adobe Express

4 folder rules for self-service velocity

  1. 1
    Always select the AEM Author repository in Content Advisor Selecting the Author repository in Adobe Express preserves your folder tree, Collections, Saved Searches, AI Search, and brief upload. A Delivery repository flattens all assets to root and disables Content Advisor.
  2. 2
    Use DM-enabled folders to bridge Express’s 80 MB import cap Adobe Express web caps direct raster uploads at 80 MB (40 MB mobile). Enabling Dynamic Media on master folders lets users drag a crisp ~2.5 MB DM rendition of a 300 MB master TIFF straight from the asset’s Dynamic Media tab.
  3. 3
    Carve out dedicated express-adaptations/ write folders Keep /brand-foundation and /products read-only for marketers and open write access on campaign output folders. Exporting All Pages of a multi-page canvas as PNG/JPEG auto-creates a child folder inside that destination.
  4. 4
    Disable Content Hub Auto-approval for Embedded Express When saving to Content Hub (where mandatory Project/Campaign Name metadata routes files into hydrated folders), disable Auto-approval and stamp Status = Under Review via Metadata Profile so unvetted drafts do not publish automatically.

Governance Matrix

Bind permissions and metadata profiles high in the tree

Configure security and automation once at Level 1 or Level 2 and let inheritance carry them downward. Follow three operational rules to keep access clean and auditable:

1. Groups, never individuals

Assign every ACL to role-based groups (express-creators, brand-stewards) so onboarding or offboarding never requires folder edits.

2. Allow-centric inheritance

Start restrictive and grant explicit Allow privileges top-down; avoid deep subfolder Deny rules that become brittle to debug.

3. Metadata-Driven Permissions

In AEMaaCS, layer attribute policies (e.g., Status = Approved) when visibility must vary inside the same folder branch.

Anti-Patterns & Checklist

Five folder traps to avoid — and how to refactor them

Nearly every expensive DAM restructuring engagement stems from one of these five anti-patterns introduced during initial setup. Pressure-test your proposed folder tree against each pair before migrating files.

Trap 01 · Org-Chart Folders Mirroring internal team names (/mktg-squad-b/)

Teams reorganize every 12–24 months; renaming published JCR paths breaks live links or strands CDN assets.

→
Best-Practice Refactor Organize by enduring content domains

Anchor Level 1 on stable business domains (/products, /campaigns, /brand-foundation) that outlast reorgs.

Trap 02 · Format Silos Splitting Level 1 by file type (/images, /videos, /pdfs)

Scatters a single campaign across three distant trees and forces admins to maintain duplicate Metadata Profiles.

→
Best-Practice Refactor Group by campaign or product; filter by MIME facet

Store mixed formats together in their campaign/product leaf and use built-in File Type facets in Omnisearch and Express.

Trap 03 · Channel Duplication Copying files per channel (/web/hero.jpg, /social/hero.jpg)

Triples storage, splits version history, triggers Dynamic Media ID collisions, and leaves expired copies live.

→
Best-Practice Refactor Store one master; deliver crops via Dynamic Media

Keep one canonical file, serve channel ratios via Smart Crop / Image Presets, and bundle kits with Collections.

Trap 04 · Open Folder Sprawl Letting all contributors create root or Level-2 folders

Spawns thousands of ungoverned folders (/Johns_Test, /New Folder 2) missing Metadata and Image Profiles.

→
Best-Practice Refactor Lock Levels 1–2 to DAM Administrators

Permit contributor subfolder creation only inside scoped /campaigns/<YYYY>/ and /wip-studio/ containers.

Trap 05 · Unpartitioned Dumps Bulk-uploading 12,000 legacy files into /legacy-import

Breaches the 1,000-asset ceiling, slows UI listings, and syncs unvetted files into Dynamic Media and Express.

→
Best-Practice Refactor Stage in batches + enrich via CSV bulk metadata

Partition folders first, apply required metadata via CSV import, and promote only active, rights-cleared assets.
