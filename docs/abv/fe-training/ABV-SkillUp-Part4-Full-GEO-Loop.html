The case · brief and scope

A free 16-night festival where AI answers decide the evening

Heritage SG, part of the National Heritage Board, runs SNF 2026 — Where Legends Unfold — Aug 21 – Sep 5 across Bras Basah.Bugis. Visitors ask AI what’s on tonight, what it costs, how to get there, and when shows start before they leave home.

Point at three things. 1 — the dates and venue appear only inside the key-visual image: no H1, no text date, and the meta description has none. Visitors see them; an agent reading the page text doesn’t, so AI fills the gap from older sources (Finding 2). Change 1 adds them as page metadata — Event schema and a meta description — so nothing changes for visitors. 2 — each program card links to its own page; in the scenario, those are the pages agents can’t read (Finding 1). 3 — the footer’s on-site AI guide only helps people already on the site; GEO is about the answers they get before they arrive. The live page won’t reflect the scenario’s changes.

The brand is Heritage SG — the same brand the Prompt Library filters on — and the festival’s names are aliases, so an answer naming either counts as a mention. SNF2026 and SGNightFest come from the site’s own keywords and hashtags. Don’t alias the parent, National Heritage Board: every NHB mention would count as yours. Other brands tracking holds the comparison set; the market is Singapore · English on heritage.sg. Brand setup has no platform field — the three platforms are a scope decision for the cohort.

Read the tree top to bottom: each layer depends on the one above. If agents can’t get in (01) or can’t read the page (02), nothing below can move — so those are gates.

Gates first. Agentic Traffic comes from CDN logs and shows agent requests, not human visits: 7,480 requests, 38% refused with a 403, about half of robots.txt fetches failing, and chatbots making 76% of requests. ABV’s success rate counts 2xx and 3xx (60%), which is why the KPI tree uses clean 2xx.

Readability is the finding teams most often miss. Access looks “fixed” once a page returns 200 — but if the content is rendered client-side, the agent receives an almost empty page.

Recover Content Visibility measures the share of page content visible to AI agents per URL and estimates the gain from prerendering. Here the official program pages are 18% readable — which is exactly why AI quotes a travel blog for show times (next finding).

Show it live with the free AI Content Visibility Checker Chrome extension, powered by ABV — no license needed. Open a content-rich page (a program page, not the homepage) and click the icon: the citation readability score is the share of the page agents can read. Detailed analysis puts the agent view beside the human view and highlights what agents miss. On /programs it read 18%, the same as RCV across all 24 URLs, because they share one client-rendered template — so check one page per template.

Know its limits. It reads one page at one moment. It fetches as ChatGPT’s crawler and, if refused, falls back to the HTML before JavaScript — so it shows readability, not the 403 rate. Access, trends, and the fix stay in ABV.

Planning & cost is partly targeted: the five prompts tagged Ticket fix were covered by the Sep 1 “Free entry” hub schema fix and the Sep 16 “Is SNF free?” FAQ; the other 11 had no content built for them. Seven planning prompts name the festival (bold) and already mentioned it, so the ticket fix moved accuracy more than presence. That is why the group moved less (44% → 52%) and sits outside both the targeted and control groups.

Branded festival prompts name the festival or Heritage SG and were not targeted. AI already answers them well (94%), so they show whether anything outside the work moved — platform changes, seasonality, the festival ending. They held at 93%. The control guards Brand Visibility — mostly against a fall, since 94% is near the ceiling. It doesn’t guard accuracy: the fact fixes reach these answers too.

In ABV’s newer dashboard, the SNF loop v1 tag filter gives targeted, partly targeted and control directly, and the Sub-category filter gives each group. The classic dashboard has no tag filter: read each group with the Topic filter and add response counts — don’t average percentages.
